# v0.5.3 — Task Library, Project Hub & Bilingual Experience

## Navigation and identity

The root opens Home, never a default active task. Home, Challenges, My Projects and Resources are distinct client views. Challenges opens a preview; Start creates a new learner project. Continue opens a specific saved instance. Wind-Powered Car is one of five examples only. The view is not encoded in the URL: refreshing returns Home unless an explicit task query is supplied.

A **Task** is a validated reusable assignment. A **Project** is one learner's instance with its own ID, canonical task snapshot, stage, completed stages, support level, thinking records and last-opened time. Editing a library definition does not overwrite existing projects. Restart requires confirmation and clears learning state while keeping the library definition.

## Local storage

`stempath-task-library-v1` holds task definitions; `stempath-projects-v1` holds projects. Every loaded item is validated. Invalid records are skipped and malformed collections safely become empty. Storage failure is surfaced in the UI. An old session task (`stempath-task-v3`) is migrated once into Recent Projects without automatically entering it. Old singleton stage progress is not guessed or attached to another task.

Projects and notes stay in this browser/device. Chat, uploaded image object URLs and adaptive transient state remain in memory and reset when leaving the workspace or refreshing. There is no database, login or cloud sync. Clearing browser data removes local work. Export task JSON to preserve reusable assignments; task export does not include learner project records. Research exports remain available separately. Browser storage is not a secure research archive.

## Task Library

Teacher/research mode (`?research=1`) exposes create/edit/duplicate/delete, validated JSON import, single/library JSON export, preview and assignment. Title and description are required; lesson, grade, subject, duration, safety and other metadata are optional. A duplicate gets a new ID. Imported text is untrusted task data, never system policy. The optional AI Task Check is not implemented in this release.

## Languages

`src/lib/i18n` centralizes English/Chinese UI strings. Chinese is the initial default; the header persists preference under `stempath-language-v1`. Task translations use optional `translations['zh-CN'|'en']` fields, preserving the canonical task ID. Existing single-language definitions remain valid. Switching UI language does not restart or duplicate a project. Original task content remains visible when no translation exists; student-authored records and existing AI messages are not machine-translated. English title/description can be authored in the form; other translated fields can be imported through JSON.

## Provider and research compatibility

The server receives the selected task context, including objectives, constraints, criteria, materials, subject, grade and safety. Teacher notes and alternate translations are excluded from the provider payload. UI language establishes the initial response language; a student's message may deliberately switch language. Auto, DeepSeek and Demo remain available in researcher controls. NO_AI makes no provider calls. Keys stay server-side; local no-key Auto uses Demo.

Research keeps legacy run-level `taskId` for compatibility, adds explicit `taskRunId`, and records stable pseudonymous `definitionId` across language versions, plus interface/task language. The pseudonym is a deterministic non-cryptographic hash, not a privacy guarantee or encryption; custom raw IDs are omitted from exports because they may contain personal text. New project openings start a fresh research run. Controlled condition resets preserve existing condition behavior. Explicit `?task=<id>` and `injectTask()` open a validated preview; researcher assignment and seeded assignment remain workspace controls.

Normal students do not see condition codes, provider/model selectors or token counters. Research mode is a UI convention, not an access-control boundary.

## Future migration

Before v0.6, define authenticated task/project ownership, consent and retention, server-side access controls and quotas, and durable research export/versioning. Map existing canonical task IDs and project IDs into database records through explicit validated migration; preserve project snapshots and task revision identity. No account, database, billing or Vercel configuration is added in v0.5.3.
